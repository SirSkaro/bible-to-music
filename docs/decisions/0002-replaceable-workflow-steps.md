# ADR 0002 · Persist decisions and reconcile paid work

**Decision.** The application decides whether to plan, generate, listen, repair, retry or stop. An artist may propose a different genre only within the producer's authority. Mureka generates performances or an available region edit. SoundCraft via its local CLI/MCP adapter renders local repairs. A selectable listener supplies observations. SQLite holds run state and the operation ledger. Local files hold immutable audio revisions. Store secret references in settings and resolve credentials through the OS credential store or environment.

**Reason.** A process can fail after submission and before a provider job ID is saved. Persist the operation identity and reserve the conservative maximum charge before submission. In the same transaction reserve the required full-song attempt slots for that passage. A multi-choice request for two performances takes two slots. Known acceptance consumes the slots even if the provider later fails. A confirmed zero-work rejection releases them. Settlement converts the reservation to actual spend and releases the excess. A cap with no usable price bound prevents submission.

**Recovery.** Reconcile the same identity and poll an existing job on restart. Keep an uncertain submission reserved until evidence resolves it. Use provider idempotency when the adapter can demonstrate it. Distinct operations must also contend safely for the same remaining funds. Region edits consume a bounded repair allowance and any billable cost. Imported audio uses zero generation attempts. Retain the parent audio and review the complete rendered revision.

**Durability choice.** Start the offline slice with ordinary Python calls. Consider LangGraph for persistence of a real paid or paused use case once crash/restart and replay contracts exist. The ledger stays the sole authority for spending. Persist progress independently of the GUI.
